# brain.readyforllm.com — API Reference

**Canonical API reference for `rfllm-brain`.**

This file is the single source of truth for how any client (`rfllm-app`, `rfllm-marketing`, internal tooling) talks to the brain worker. The file is mirrored verbatim into the sibling repos via symlink. Any change to an endpoint's contract must be reflected here in the same PR.

- **Base URL (production):** `https://brain.readyforllm.com`
- **Base URL (local dev):** `http://localhost:8787`
- **Architecture version:** v2 (post Phase 0.5 + Phase 0.5b, audit 2026-04-17)

**Last major cleanup:** Phase 0.7 (2026-04-17) — v1 crawler-infrastructure surface removed. If you find references to `/analyze`, `/crawl`, `/broadcast`, `/deploy`, `/notify`, or v1 `/competitors` semantics, they are historical and should not be re-implemented without an explicit product-direction decision.

This worker is a single-file Cloudflare Worker whose router lives in `src/index.ts`. It uses the Supabase **service-role** key and bypasses RLS — treat every non-`/public/*` endpoint as privileged.

---

## Authentication

The worker exposes three authentication modes. The check is a global gatekeeper in `src/index.ts`: requests to `/webhooks/polar` and any path starting with `/public/` bypass the gate, everything else requires the internal service secret.

### 1. Internal service secret (`x-api-key`)

Used for every endpoint that is not `/webhooks/polar` and not `/public/*`. That includes all GET admin/credit endpoints, all POST operational endpoints, cron-equivalent manual triggers, and the billing/checkout flows invoked by the dashboard.

- **Header:** `x-api-key: <INTERNAL_SERVICE_SECRET>`
- **Env var:** `INTERNAL_SERVICE_SECRET`
- **Failure mode:** `401 { "error": "Unauthorized" }`

Some endpoints additionally require `x-user-id: <supabase auth uuid>` (currently `POST /sites/create-from-onboarding` and `POST /checkout/create`). Missing that header returns `400 { "error": "Missing x-user-id header" }`.

### 2. Tool token (`x-tool-token`)

Three `/public/*` endpoints are gated behind a short-lived HMAC token minted by the marketing site:

- `POST /public/generate-preview`
- `POST /public/check-citations`
- `POST /public/estimate-size`

The token is `<payloadB64>.<signatureB64>` where `payloadB64 = base64url(JSON.stringify({purpose, iat, exp, nonce, origin, ip}))` and the signature is HMAC-SHA256 of `payloadB64` under `TOOL_TOKEN_SECRET`. TTL is 60s and each nonce is stored in KV for 5 minutes (single-use replay protection). The `purpose` field must match the endpoint being called.

- **Header:** `x-tool-token: <payloadB64>.<signatureB64>`
- **Env var:** `TOOL_TOKEN_SECRET` (shared byte-for-byte with the marketing app's Vercel env)
- **Failure mode:** `403 { "error": "Forbidden", "reason": <string> }` where reason ∈
  - `missing_token` — header absent
  - `malformed_token` — not two `.`-separated parts
  - `bad_signature` — HMAC mismatch
  - `malformed_payload` — payload is not valid base64url JSON
  - `expired` — `exp < now`
  - `future_iat` — `iat > now + 30s` (clock skew guard)
  - `wrong_purpose` — token minted for a different tool
  - `replayed_nonce` — nonce already seen in the last 5 minutes

Separately from the token gate, each tool has a daily-budget cap + kill-switch (see [Rate limits](#rate-limits)). If either trips, the endpoint returns `429 { "error": <msg>, "reason": "cap_hit" | "tool_disabled" }`.

### 3. Polar webhook signature

`POST /webhooks/polar` verifies the inbound request via `validateEvent` from `@polar-sh/sdk/webhooks` using the standard-webhooks headers `webhook-id`, `webhook-timestamp`, `webhook-signature`.

- **Env var:** `POLAR_WEBHOOK_SECRET` (pass raw, including the `polar_whs_` prefix — the SDK strips it internally)
- **Failure mode:** `401 { "error": "signature verification failed" }`

### 4. Public (no auth)

The remaining `/public/*` endpoints are fully unauthenticated. They are rate-limited per caller IP (see [Rate limits](#rate-limits)).

## CORS

`src/index.ts` allows these origins: `http://localhost:3000`, `http://localhost:3005`, `https://app.readyforllm.com`, `https://readyforllm.com`, `https://www.readyforllm.com`. Origins outside that list get the first entry in the allow-list back (effectively blocked by the browser's CORS check).

`OPTIONS` requests are answered with `204` and CORS headers. `Access-Control-Allow-Methods: GET, POST, OPTIONS`. `Access-Control-Allow-Headers: Content-Type, x-api-key`.

## Endpoints

Every endpoint returns `Content-Type: application/json` unless otherwise noted. Unmapped paths return `404 { "error": "Not Found" }`. Methods other than `GET` / `POST` / `OPTIONS` return `405 { "error": "Method Not Allowed" }`.

### Credits (internal auth)

#### GET `/credits/balance`

Look up a site's current credit balance, monthly allocation, reset timestamp, and the last 20 ledger rows.

**Query params:**
- `siteId` (required) — site UUID

**Success (200):**
```json
{
  "balance": 17230,
  "allocation": 20000,
  "resetAt": "2026-05-12T00:00:00Z",
  "recentTransactions": [
    {
      "id": "uuid",
      "type": "grant_subscription",
      "amount": 20000,
      "balance_after": 20000,
      "created_at": "2026-04-12T00:00:00Z",
      "note": "Subscription grant: growth monthly"
    }
  ]
}
```

**Errors:**
- `400 { "error": "Missing siteId" }`
- `500 { "error": "Balance lookup failed" }` — Supabase query failed

**Side effects:** two `sites` + `credit_transactions` reads, no writes.

#### POST `/credits/grant-monthly`

Manually trigger the monthly-reset sweep. Idempotent — only sites whose `credits_reset_at` is already in the past are touched. The daily cron runs the same method, so production use of this endpoint is limited to ops runbooks.

**Request:** empty body.

**Success (200):**
```json
{ "reset": 3, "errors": 0 }
```

**Errors:**
- `500 { "error": "Grant-monthly failed" }`

**Side effects:** calls `CreditService.processMonthlyResets()` — for each due monthly site, updates `sites.credits_remaining`, `credits_allocation_monthly`, `credits_reset_at`, and inserts one `credit_transactions` row of `type: 'grant_subscription'`.

#### POST `/credits/reconcile`

Audit the ledger: compare the sum of `credit_transactions.amount` per site against `sites.credits_remaining`. Reports drift, does **not** auto-correct.

**Request body (optional):**
```json
{ "siteId": "uuid" }
```
If `siteId` is omitted, reconciles every site with `deleted_at IS NULL`.

**Success (200):**
```json
{
  "drifts": [
    { "siteId": "uuid", "expected": 17230, "actual": 17240 }
  ]
}
```
`drifts` is empty when everything reconciles.

**Errors:**
- `500 { "error": "Reconcile failed" }`

### Admin (internal auth)

#### GET `/admin/tool-status`

Returns the kill-switch state and today's call count for every tool in `DAILY_BUDGET_CAPS`.

**Success (200):**
```json
{
  "tools": [
    { "tool": "generate-preview", "enabled": true, "cap": 3000, "usedToday": 124 },
    { "tool": "parasite-blocklist", "enabled": true, "cap": null, "usedToday": 0 }
  ]
}
```
`cap: null` means unlimited (`Infinity` in code).

#### POST `/admin/kill-switch`

Toggle the per-tool kill-switch. Writes KV key `tool-enabled:<tool>` with 24h TTL; disables the tool in ≤30s regardless of its cap.

**Request body:**
```json
{ "tool": "generate-preview", "enabled": false }
```

**Success (200):**
```json
{ "ok": true, "tool": "generate-preview", "enabled": false }
```

**Errors:**
- `400 { "error": "Missing tool or enabled" }` — body is missing either field or `enabled` is not a boolean
- `400 { "error": "Unknown tool" }` — `tool` is not in `DAILY_BUDGET_CAPS`
- `500 { "error": "Kill switch failed" }`

### Polar webhook (signature auth)

#### POST `/webhooks/polar`

Receives Polar subscription-lifecycle and order events. Verified via `@polar-sh/sdk/webhooks` `validateEvent`.

**Handled event types:**

| Event | Action |
| --- | --- |
| `subscription.created`, `subscription.active` | `activateSite` — sets `sites.is_active=true`, `status='active'`, writes `polar_subscription_id` / `polar_customer_id` / `current_period_end`, then grants the tier's credit allocation with the correct cadence. |
| `subscription.cycled` | `handleCycled` — refreshes `current_period_end`. For monthly subs, grants the tier allocation. For annual subs, no-op (the daily cron's `refillAnnualSubscribers` handles intra-year monthly refills). |
| `subscription.canceled` | `cancelSite` — sets `is_active=false`, `status='canceled'`. User retains access until `current_period_end`. |
| `subscription.revoked` | `revokeSite` — sets `is_active=false`, `status='revoked'`, clears `current_period_end`. |
| `order.paid` | `recordInvoice` — upserts into `polar_invoices` keyed on `polar_invoice_id`. If the order's `productId` matches a top-up SKU (`POLAR_PRODUCT_TOPUP_1K/3K/10K/30K/100K`), grants the corresponding credits with 90-day expiration via `CreditService.grantTopup`. |
| `checkout.updated` | Acknowledged, no action. |
| any other | Logged, `handled: false`. |

**Site lookup order** for every event: `data.metadata.site_id` → `polar_subscription_id` → `polar_customer_id`. If none resolves, `handled: false, siteId: null`.

**Success (200):**
```json
{ "handled": true, "type": "subscription.cycled", "siteId": "uuid" }
```
Always returns 200 on handler errors after signature verification, with `{ "handled": false, "error": "internal" }` — this prevents Polar from retrying and prevents the signature from being invalidated by a replay.

**Errors:**
- `401 { "error": "signature verification failed" }` — invalid or missing standard-webhooks headers

**Important invariants:**
- Polar SDK-validated events use camelCase field names: `customerId`, `subscriptionId`, `currentPeriodEnd`, `totalAmount`, `productId`. Do **not** look for snake_case equivalents (`customer_id`, etc.).
- Amount fields: `order.paid` uses `totalAmount`; `subscription.*` events use `amount`. `recordInvoice` falls back through both.

### Onboarding + billing (internal auth)

#### POST `/sites/create-from-onboarding`

Create the `sites` row after the marketing onboarding flow completes. Row is inserted in `status='pending_verification'`, `is_active=false` — the Polar webhook flips it active. Idempotent on `(user_id, domain)`.

**Required headers:**
- `x-api-key`
- `x-user-id` — Supabase auth user UUID

**Request body:**
```json
{
  "domain": "example.com",
  "tier": "growth",
  "billingCycle": "monthly",
  "pageCount": 340,
  "recommendedTier": "growth"
}
```

**Success (200):**
```json
{ "siteId": "uuid" }
```
If `(user_id, domain)` collides on the unique index (Postgres code `23505`), the existing row's id is returned instead.

**Errors:**
- `400 { "error": "Missing x-user-id header" }`
- `400 { "error": "Missing required fields" }` — any of `domain`, `tier`, `billingCycle`, `pageCount`, `recommendedTier` is undefined
- `500 { "error": "Failed to create site" }` — insert failed with a non-23505 error
- `500 { "error": "Site creation failed" }` — unhandled exception

#### POST `/checkout/create`

Create a Polar hosted-checkout session for the given site × tier × cycle. Returns the checkout URL to redirect to. All Polar API calls live in brain — never call `api.polar.sh` from the Vercel app.

**Required headers:**
- `x-api-key`
- `x-user-id`

**Request body:**
```json
{
  "siteId": "uuid",
  "userEmail": "user@example.com",
  "tier": "growth",
  "billingCycle": "monthly"
}
```
`tier ∈ { 'starter', 'growth', 'scale', 'enterprise' }`. `billingCycle ∈ { 'monthly', 'annual' }`.

The product is resolved by looking up env var `POLAR_PRODUCT_<TIER>_<CYCLE>` (uppercased). Checkout metadata embeds `site_id`, `user_id`, `tier`, `billing_cycle` — the Polar webhook reads these to wire the subscription back to the site.

**Success (200):**
```json
{ "checkoutUrl": "https://polar.sh/checkout/...", "checkoutId": "uuid" }
```

**Errors:**
- `400 { "error": "Missing x-user-id header" }`
- `400 { "error": "Missing required fields" }`
- `400 { "error": "Enterprise tier does not use self-serve checkout" }` — enterprise is contact-sales only
- `500 { "error": <Polar error message> }` — any Polar API failure propagates

#### POST `/billing/info`

Read-only view of a site's billing state. All fields are read directly from the `sites` row — no Polar API round-trips. Used by the dashboard billing page.

**Request body:**
```json
{ "siteId": "uuid" }
```

**Success (200):**
```json
{
  "tier": "growth",
  "billingCycle": "monthly",
  "currentPeriodEnd": "2026-05-12T00:00:00Z",
  "creditsRemaining": 8420,
  "creditsAllocationMonthly": 10000
}
```

- `tier` ∈ `'starter' | 'growth' | 'scale' | 'trial'` (also `'enterprise'` if provisioned).
- `billingCycle` reads `sites.billing_cadence` ∈ `'monthly' | 'annual'`.
- `currentPeriodEnd` is populated by the Polar `subscription.created` / `subscription.cycled` webhook; `null` before first activation or after revocation.

**Errors:**
- `404 { "error": "Site not found" }` — no site row or already soft-deleted
- `500 { "error": "Billing processing failed", "details": "<message>" }`

#### POST `/public/estimate-size`

Call Firecrawl `/v1/map` on the domain, return page count and recommended tier. Hard 20s handler ceiling; Firecrawl fetch has its own 15s abort.

**Auth:** tool token, purpose `estimate-size`.

**Request body:**
```json
{ "domain": "example.com" }
```

**Success (200):**
```json
{
  "pageCount": 340,
  "recommendedTier": "growth",
  "firstFewUrls": ["https://example.com/", "https://example.com/about"]
}
```
`firstFewUrls` is the first 10 mapped URLs. `recommendedTier` comes from `recommendTier(pageCount)` in `src/lib/tiers.ts`: ≤100 → `starter`, ≤1000 → `growth`, ≤5000 → `scale`, else `enterprise`.

- `400 { "error": "Invalid domain" }`
- `403 { "error": "Forbidden", "reason": <token-reason> }`
- `429 { "error": "Rate limit exceeded. Try again in a minute." }`

- `502 { "error": "Size estimation failed" }` — Firecrawl returned non-2xx or the fetch threw
- `504 { "error": "Size estimation timed out" }` — 20s handler ceiling

**Side effects:** one Firecrawl `/v1/map` call (costs 1 Firecrawl credit per call, not per URL), one `free_scan_leads` insert.

## Crons

`wrangler.jsonc` declares one cron schedule:

### `0 0 * * *` — daily midnight UTC

In order, via `ctx.waitUntil` (sequential within the async IIFE, each wrapped in try/catch):
1. `CreditService.refillAnnualSubscribers()` — grants the monthly allocation to any `billing_cadence='annual'` site whose `last_monthly_refill_at` is ≥ 30 days old. Balance is **replaced**, not incremented (matches monthly behavior).
2. `CreditService.expireTopupCredits()` — deducts expired top-up grants (sweeps `credit_transactions` rows of `type='grant_topup'` with `expires_at < now()` that do not yet have a matching `expiration` row). Writes offsetting `expiration` ledger rows. Clamps the expiration amount to current balance (see method comment for the approximation rationale).
3. `CreditService.processMonthlyResets()` — safety-net re-grant for `billing_cadence='monthly'` sites whose `credits_reset_at` has elapsed (should normally already have been handled by `subscription.cycled`).

## Rate limits

### Per-IP tool limits

Enforced in `PublicService.rateLimit` using KV key `rl:<tool>:<ip>`. `cf-connecting-ip` is the source of truth for the IP. Localhost origins bypass.

| Tool | Limit | Window |
| --- | --- | --- |
| `check-manifest` | 10 | 60s |
| `auditRobots` | 10 | 60s |
